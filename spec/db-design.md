## 2. 設計原則（與舊版的差異）

1. **交易採「兩端」模型。** 每筆交易有「來源」與「目的」兩端，每端都是（帳戶、標的、數量），任一端可為空。餘額 = Σ目的 − Σ來源。收入、支出、轉帳、換匯、買賣股票、股息、還款全部用同一套算法，不再為每種類型寫專屬邏輯。
2. **貨幣與投資標的統一成「標的」。** TWD、USD、0050、VOO、BTC、Line 點數都是標的。換匯與買股票因此是同一種交易，舊版為了跨幣別買股加的 `settle_amount`／`settle_currency`／`fee_currency` 三個欄位不再需要。
3. **一個帳戶可以持有多種標的。** 證券帳戶同時有台幣現金與股票，加密交易所同時有 USDT 與 BTC。舊版被迫把「元大證券」和「元大交割戶」拆成兩個帳戶，這個補丁可以拿掉。
4. **衍生資料不存進資料庫。** 餘額、持倉、平均成本、淨值都由 Apps Script 即時計算，只有每日淨值快照會寫回 Sheet。舊版的 `holdings`、`dashboard` 兩張表因此不再需要（公司電腦改看網頁，不用直接看 Sheet）。
5. **Sheets 公式只用在 Sheets 才有的能力**（GOOGLEFINANCE、IMPORTDATA）。交易與帳戶不放 SUMIFS 這類公式，避免資料量大時變慢，也避免公式與程式邏輯雙軌維護。
6. **金額精度。** Sheet 裡存自然單位（例如 USD 100.25），計算時先依標的小數位數轉成整數最小單位再加減，最後才轉回顯示。BTC 的 0.1 + 0.2 因此剛好是 0.3，不會有浮點誤差。
7. **軟刪除。** 交易不實體刪除，改標記「作廢」。任何寫入都記進異動紀錄。
8. **容忍你直接在 Sheet 手動編輯。** 以 ID 而不是行號當識別；讀取時若某列資料不合法，只在「資料檢查」清單標出來，不讓整個系統壞掉。
9. **寫入一律加鎖。** ID 產生與寫入使用 LockService；一次寫多筆（例如繳卡費分攤）用單次 setValues，要嘛全成功、要嘛全失敗。

## 3. 整體架構

```
手機／電腦／平板
   │  HTTPS
   ▼
GitHub Pages（靜態網站：HTML/CSS/JS + manifest + service worker）
   │  fetch POST（Content-Type: text/plain，避免 CORS 預檢）
   ▼
Apps Script Web App（部署：以我的身分執行、任何人可存取，但每個請求都要驗證）
   │  SpreadsheetApp
   ▼
財務 Google Sheet（私人，不對外分享）
```

- GitHub Pages 的網站內容是公開的，所以 **repo 裡絕對不放** token、PIN、Sheet ID、任何資料。Sheet ID、PIN 雜湊、token 雜湊都放在 Apps Script 的 Script Properties。
- 前端只知道 Web App 的網址；沒有 token 與 PIN 就什麼都拿不到。
- 排程（Apps Script 時間觸發器）：每日更新價格與寫入價格歷史、執行「自動入帳」的定期交易並為其他執行方式產生「待確認」、寫入淨值快照、寄提醒信（定期到期、資金備妥、交割前備妥款項、信用卡繳款日將近）。這是網頁版比 Android 版多出來的能力。

### 登入流程
1. 每台裝置第一次使用時輸入「裝置授權碼」，存在該裝置的 localStorage。
2. 每次開啟（或閒置超過設定時間）輸入 PIN。
3. 後端驗證兩者；連續錯誤達上限（暫定 5 次）鎖定一段時間，失敗計數存在 CacheService。
4. 驗證成功回傳短效工作階段碼，後續請求帶這個工作階段碼。

### 價格
標的代號、現價、上次有效價、計價幣別、更新時間、狀態（正常／沿用舊值／缺價格）。現價欄用 GOOGLEFINANCE 或 IMPORTDATA 公式；公式出錯（#N/A）時，每日排程改用「上次有效價」並把狀態標成「沿用舊值」，不會讓總資產突然變成錯誤。「上次有效價」是實作時新增的欄位：因為現價欄是公式，出錯時舊值會一起消失，所以要另存一份。

### 價格歷史

### 休市日
| 欄位 | 說明 |
|---|---|
| 市場 | 台灣／美國 |
| 日期 | |
| 名稱 | 例如「農曆春節前最後交易日」「市場無交易，僅辦理結算交割作業」 |
| 有交易 | 是／否 |
| 有辦理交割 | 是／否。台灣「市場無交易、僅辦理結算交割作業」的日子：有交易＝否、有辦理交割＝是 |
| 來源 | 證交所匯入／程式產生／手動 |

- 週六、週日一律視為沒有交易、沒有交割，不需要列在表裡。
- **台灣**：每年由排程從證交所公開的「開休市日期」資料匯入。該資料只提供當年、日期為民國年格式，程式會轉換；名稱含「最後交易日」「開始交易日」的列只是提示，並非休市，匯入時略過。
- **美國**：由程式依規則（新年、馬丁路德金日、總統日、耶穌受難日、陣亡將士紀念日、六月節、獨立紀念日、勞動節、感恩節、聖誕節，遇週末的補假規則）產生。
- **臨時休市（颱風、地震）無法預測**，表裡不會有；發生時請手動補一列，並把受影響的交易的交割日改正。

日期、現金存款、外幣現金、股票與 ETF、加密、應收、信用卡負債、貸款負債、應付、總資產、總負債、淨資產。皆換算為基準幣別（TWD）。

### 異動紀錄
時間、動作（新增／修改／作廢／重算）、資料表、資料ID、摘要、裝置。

## 6. 各交易類型如何填兩端

| 類型 | 來源 | 目的 | 說明 |
|---|---|---|---|
| 收入 | — | 帳戶、標的、金額 | 需要分類 |
| 支出 | 帳戶、標的、金額 | — | 需要分類 |
| 轉帳 | 帳戶 A | 帳戶 B | 標的與數量相同；信用卡還款、代付、報帳都是轉帳 |
| 換匯 | 帳戶、幣別 A、金額 | 帳戶、幣別 B、金額 | 匯率由兩端相除得出，不另存 |
| 買入 | 付款帳戶、現金標的、**實際扣款金額** | 證券帳戶、投資標的、數量 | 填成交金額、手續費、交割日；台股實付 = 成交金額 + 手續費；複委託台幣交割時，實付台幣 = （成交金額 + 手續費）× 券商匯率 |
| 賣出 | 證券帳戶、投資標的、數量 | 收款帳戶、現金標的、**實際入帳金額** | 填成交金額、手續費、稅款、交割日；台股實收 = 成交金額 − 手續費 − 稅款 |
| 股息 | — | 帳戶、現金標的、實收金額 | 填關聯標的；成交金額 = 稅前股息，實收 = 稅前 − 手續費 − 稅款。配股則目的填該標的股數（成本 0，不算現金收入） |
| 股數調整 | 併股時填減少的股數 | 拆股時填增加的股數 | 只改股數、總成本不變（拆股、併股、標的更名） |
| 退款 | — | 原付款帳戶 | 填關聯交易ID與同分類 |
| 調整 | 餘額調少時填 | 餘額調多時填 | 對帳用；UI 提供「輸入實際餘額，自動算差額」 |

## 7. 計算規則

**帳戶餘額（截至某日）**：對每個（帳戶、標的）加總所有「有效」交易的兩端：Σ目的數量 − Σ來源數量，以整數最小單位計算。每一端算入的日期不同：**現金（法幣）用交割日，股票等其他標的用成交日**；沒有交割日的交易，兩者都用日期。細節見 7.4。

**淨值**：所有（帳戶、標的）餘額乘上該標的價格，再換成基準幣別後加總。

**持倉與平均成本（預設平均成本法）**：每個持倉（帳戶 × 標的）同時記錄三個數字：持有股數、**計價幣別成本**（美股為 USD）、**台幣成本**。

- 買入：股數增加；計價幣別成本 += 成交金額 + 手續費（+ 稅款）；台幣成本 += 實際扣款的台幣金額。**手續費因此算進投資成本**，不會出現在一般支出。
- 賣出：成本（兩種幣別）按「賣出股數 ÷ 持有股數」的比例扣除。
  - 已實現損益（計價幣別）= 成交金額 − 手續費 − 稅款 − 被扣除的計價幣別成本
  - 已實現損益（台幣）= 實際入帳的台幣 − 被扣除的台幣成本
- 配股、拆股、併股：只改股數，總成本不變（所以每股均價會跟著變）。
- 未實現損益 = 市值 − 剩餘成本（兩種幣別都算）。

**外幣資產（複委託）的台幣報酬會拆成兩部分**，讓你看得出賺的是股價還是匯率：

- 股價損益 =（市值 − 計價幣別成本）× 現在匯率
- 匯兌損益 = 計價幣別成本 ×（現在匯率 − 平均買入匯率）
- 兩者相加恆等於「台幣市值 − 台幣成本」。平均買入匯率 = 台幣成本 ÷ 計價幣別成本，來自你每次實際的台幣扣款，所以包含券商匯差。

**輸入檢查**：
- 台股（同幣別）：實付必須等於成交金額 + 手續費，不符就提示。
- 複委託：系統反推「隱含匯率」＝ 實付台幣 ÷（成交金額 + 手續費），與市場匯率差距超過門檻（暫定 3%）時警告，可抓到少打一位數之類的輸入錯誤。券商匯率本來就會比市場匯率略差，所以只警告、不阻擋。

**若用美元帳戶買入美股**：台幣成本沒有實際的台幣扣款可對照，改以買入當日匯率（取自價格歷史）估算，並在畫面上標示為「估算」。

**信用卡帳單**：依結帳日切分區間，累計該區間內以該卡為來源的支出，並扣掉退款與還款；繳款日前顯示待繳金額。銀行一次繳多張卡時，分攤成多筆同群組的轉帳。

**貸款**：餘額為負；每月還款依貸款設定與還款方式拆成本金與利息。

**淨值曲線與報表**：以「快照」為主，歷史某日的持倉估值用「價格歷史」補足。

### 7.1 數字精度與四捨五入

| 項目 | 規則 |
|---|---|
| 數量與金額 | 依該標的的「小數位數」：TWD 0、JPY 0、USD 2、BTC 8、台股股數 0、複委託美股碎股 5（可在標的表調整）。輸入超過位數時提示或拒絕 |
| 加減運算 | 一律先轉成整數最小單位再運算（TWD 存元、USD 存分、BTC 存聰），最後才轉回顯示。整數最大約 9×10^15，即使持有 1000 顆 BTC 也只有 10^11，遠在安全範圍內 |
| 價格與匯率 | 不是「金額」，不強制位數，保留原值（例如 USDTWD 31.5432），只用在估值 |
| 換匯 | 兩端金額各依自己標的的精度；匯率由兩端相除顯示，不另外儲存 |
| 成本與損益 | 中間計算保留完整精度，不逐筆四捨五入，避免誤差累積；寫入報表或顯示時才依該幣別位數進位 |
| 換算成台幣的總額 | 先以完整精度加總，最後才四捨五入到整數。明細各自進位後相加，可能與總額差 1 元，屬正常現象 |

### 7.2 收支報表的計算規則（哪些算收入、支出，哪些不算）

只有資金「真的進出你的整體資產」才算收支；資金只是在自己的帳戶之間移動，不算。

| 類型 | 收入 | 支出 | 說明 |
|---|---|---|---|
| 收入 | 計入 | | |
| 支出 | | 計入 | 信用卡刷卡在「刷卡日」就計入支出 |
| 轉帳 | 不計 | 不計 | 包含信用卡還款、代付（轉到應收）、報帳、貸款本金；因此刷卡再還款不會重複計算 |
| 換匯 | 不計 | 不計 | 只是把資產換一種幣別 |
| 買入 | 不計 | 不計 | 資產轉換；手續費算投資成本，列在投資報表 |
| 賣出 | 不計 | 不計 | 資產轉換；已實現損益列在投資報表 |
| 股息 | 計入（實收） | | 分類為「股息」；收入取實收金額，稅前金額與預扣稅列在投資報表。配股不算現金收入 |
| 股數調整 | 不計 | 不計 | 拆股、併股，只改股數 |
| 退款 | | 沖抵 | 沖抵同分類的支出，報表顯示淨額 |
| 調整 | 不計 | 不計 | 對帳差額，另外獨立列出 |

貸款還款：利息是「支出」，本金是「轉帳」，所以每月只有利息影響收支。

對帳關係：**淨值變動 = 收入 − 支出 + 投資損益（含手續費） + 匯兌損益 + 調整**。這條等式可以用來檢查資料是否有漏記。

### 7.3 台股與複委託（用台幣買美股）的記法

**台股整股／零股／定期定額**：來源填付款的銀行（或交割）帳戶與實付台幣，目的填證券帳戶、股票與股數；成交金額與手續費填台幣，實付 = 成交金額 + 手續費。台股股數為整數，所以標的的小數位數設 0。

**複委託（台幣交割）**：券商用台幣扣款，再以券商匯率換成美元下單，對帳單上的成交金額與手續費都是美元。新增交易時照對帳單填：

| 欄位 | 範例 |
|---|---|
| 類型 | 買入 |
| 來源 | 綁定的台幣銀行帳戶、TWD、32,074（實際扣款） |
| 目的 | 複委託帳戶、VOO、2 股 |
| 成交金額／手續費／稅款 | USD 1,000／USD 15／0 |
| 隱含匯率（系統算，不存） | 32,074 ÷ 1,015 = 31.6 |

再買一次（1 股、成交 USD 520、手續費 USD 15、匯率 32.0、實付 TWD 17,120）之後，持倉與損益如下（現價 USD 600、匯率 32.5）：

| 項目 | 數字 |
|---|---|
| 持有 | 3 股 |
| 美元成本 | USD 1,550（含兩次手續費） |
| 台幣成本 | TWD 49,194 |
| 平均買入匯率 | 31.74 |
| 市值 | USD 1,800 ＝ TWD 58,500 |
| 台幣未實現損益 | +9,306 |
| 其中股價損益 | +8,125 |
| 其中匯兌損益 | +1,181 |

接著賣出 1 股（成交 USD 610、手續費 USD 15、匯率 32.4，入帳 TWD 19,278）：被扣除的成本為 USD 516.67／TWD 16,398，已實現損益為 USD +78.33、**台幣 +2,880**。

**美股股息**：稅前 USD 3.60、預扣稅 USD 1.08 時，類型選股息，關聯標的填 VOO，成交金額 3.60、稅款 1.08，實收 USD 2.52 進複委託帳戶（或已由券商換成台幣入銀行）。之後若要換成台幣，再記一筆換匯。

**拆股、併股**：用「股數調整」，只改股數、不動總成本。

**定期定額買股票**：見 7.5。

### 7.4 交割日：預設值、待交割款與提醒

**為什麼要有交割日。** 買股票時，成交當天股票就記在你名下，但銀行的錢要等交割日才扣；賣股票則相反。如果只記一個日期，這幾天的銀行餘額會和你的銀行 App 差一筆。

**預設交割日 = 成交日後第 N 個營業日**，N 與營業日曆由證券帳戶設定決定，手動修改後以你填的為準：

| 情境 | 預設 N | 營業日曆 |
|---|---|---|
| 台股買入、賣出 | 2 | 台灣（有辦理結算交割的日子） |
| 複委託買入 | 1 | 台灣＋美國，兩邊都營業 |
| 複委託賣出 | 2 | 台灣＋美國，兩邊都營業 |

你的券商是元大：元大複委託作業手冊載明買進款項於成交後「次一營業日」扣除，與上表的複委託買入 T+1 一致；賣出入帳日請以你的對帳單核對。

複委託的天數依券商不同，且美股結算制度近年調整過（2024 年 5 月起改為 T+1），所以這些數字是「預設值」，放在證券帳戶設定裡由你調整，不寫死在程式裡。

**春節封關的特殊算法。** 證交所在春節前後會標示幾天「市場無交易，僅辦理結算交割作業」。這些日子雖然不能買賣，但交割照常辦理，所以要算營業日。例如 2026 年封關前最後交易日 2/11 成交，T+2 是 2/13，而不是開紅盤後的 2/24。程式因此把「有辦理交割」的日子當營業日，而不是只看有沒有交易。

**待交割款。** 成交日到交割日之前，系統自動把這筆交易算成一筆「待交割款」（買入為待付、賣出為待收），顯示在該銀行帳戶旁並計入淨值：

- 銀行餘額維持與銀行 App 一致，交割日當天才變動。
- 股票從成交日起就計入持倉。
- 待交割款抵掉這段期間的落差，所以**淨值在成交日、交割日前後都不會跳動**。若沒有這一項，買股票後那兩天的淨值會多算一筆錢。

**報表用哪個日期。** 收支、投資損益、持倉以成交日為準；銀行帳戶對帳、現金流以交割日為準。

**交割提醒。** 排程會在交割日前一個營業日寄信：「XX 帳戶明天需備妥 NT$XXX 交割款」，避免台股餘額不足而違約交割；賣出則提醒款項預計入帳日。

**修改交易時。** 更改成交日後，若交割日仍是自動帶出的值，系統會詢問是否一併重算；已手動改過的交割日不會被覆蓋。

### 7.5 定期定額與定期交易的流程

**同一份「定期」範本，用「執行方式」區分四種做法。** 差別在於「誰下單、錢什麼時候扣」，這也決定了成交日與交割日怎麼算。

| 執行方式 | 誰下單、何時扣款 | 到期時系統做什麼 | 成交日 | 交割日 | 例子 |
|---|---|---|---|---|---|
| 自動入帳 | 不涉及券商，金額固定 | 直接寫入一筆「有效」交易 | 到期日 | 同成交日 | 房租、固定轉帳到儲蓄帳戶 |
| 提醒確認 | 金額每次不同 | 產生「待確認」，你確認或修改金額後入帳 | 到期日 | 同成交日 | 電話費、水電費 |
| **券商定期定額** | 券商在約定日直接扣款並成交 | 產生「待確認」，等券商成交後你填實際結果 | 預計扣款日 | **同成交日（當天扣款）** | 元大台股／美股定期定額 |
| **手動下單** | 你自己在當天下單，走一般買進 | 當天產生「待確認」提醒你去買，買完你回來填 | **你實際下單成交的日子** | **成交日後第 N 個營業日（台股 T+2），自動算出、可改** | 手動買正二、手動的定期不定額 |

這樣「有些當天扣款、有些要等交割日」就是兩種不同的範本，各自設定，不會互相影響。兩種可以同時存在，即使是同一天：

- 券商定期定額那筆：當天銀行餘額就減少，沒有待交割款。
- 手動下單那筆：成交後股票立刻入帳，但銀行要等交割日才扣款，中間顯示「待交割款」，淨值不會跳動。

#### 流程 A：券商定期定額（例如元大）

1. **設定範本。** 例如：每月 6 號、來源＝元大交割戶、目的＝元大證券的 0050、預計投入 NT$3,000、執行方式＝券商定期定額。可以填多個日期。
2. **資金備妥提醒。** 元大台股定期定額要求在扣款日前一營業日 16:00 前把款項存入交割帳戶，所以預計扣款日的前一個營業日，系統寄信提醒。
3. **到期產生「待確認」。** 預計扣款日到了（遇假日順延到下一個有交易的日子，與元大台股的做法一致），系統產生一筆「待確認」，首頁顯示「N 筆待確認」。待確認的交易不影響餘額、持倉、淨值與報表。
4. **你填入實際成交結果。** 券商成交後（元大會以電子平台、簡訊或語音回報），打開待確認，畫面已預填帳戶、標的、預計金額，你補：實際扣款金額、成交股數、成交金額（美股為美元）、手續費（依「證券帳戶設定」的定期定額手續費建議）。確認後才入帳。
   - 實際金額可以和預計不同（手續費、匯率、券商的「定期不定額」加減碼），所以券商的定期不定額也適用同一個流程。
   - 同一天有多檔時，提供批次確認畫面。
5. **沒成交就略過。** 餘額不足等原因未成交時選「略過」。元大公開的規則是：台股餘額不足時當次不執行、也不補扣；複委託遇到某筆圈存款項不足時，會跳過該筆。
6. **忘記確認也不會漏。** 待確認會一直留在清單上，超過設定天數會寄信提醒。

#### 流程 B：手動下單（手動買正二、手動的定期不定額）

1. **設定範本。** 例如：每月 10 號、來源＝元大交割戶、目的＝元大證券的 00631L、預計金額 NT$20,000、執行方式＝手動下單。預計金額只是預設值，每次實際買多少由你決定，所以「定期不定額」就是每次確認時填不同的金額。
2. **當天提醒。** 到期當天早上產生「待確認」並寄信：「今天該買 00631L，預計 NT$20,000」。
3. **你自己去下單。**
4. **回來填成交結果。** 填實際成交日（預設是提醒日；如果你等到別天才買，就改成實際的日子）、成交股數、成交金額、手續費。**交割日自動算成「實際成交日後第 N 個營業日」**（N 取自證券帳戶設定，元大台股預設 2），可手動修改。
5. **交割前提醒。** 確認後銀行會出現「待交割款」；交割日前一個營業日寄信提醒備妥款項，避免餘額不足違約交割。
6. **今天沒買：延後或略過。** 「延後」可把預計日改成另一天，仍是同一筆待確認、不會多產生一筆；「略過」則這期不買。

#### 系統怎麼避免出錯

- 是否已產生過，以（定期ID、預定日）判斷。排程重複執行、很多天沒開而一次補跑，都不會重複產生。
- 待確認清單顯示「預計扣款金額」。券商已扣款、但你還沒確認的那幾天，系統的銀行餘額會比銀行 App 多這一筆，清單可以讓你對得上。
- **修改成交日時的交割日：** 不需要額外欄位。系統比對「現有交割日」是否等於「依舊成交日自動算出的結果」：是，就視為自動帶出，跟著新成交日重算；不是，就視為你手動改過，保留不動。極少見的例外：你手動填的日期剛好等於自動值，會被當成自動、改成交日時重算，這是可接受的。

#### 定期定額為什麼預設當天扣款

你已確認元大定期定額是扣款當天扣款，所以「券商定期定額」的交割天數預設為 0。元大公開文件沒有明文寫出定期定額的扣款時點，這一項是依你的實際經驗定案。若將來券商規則改變，只要改範本的「交割天數」即可，不需要改程式。

#### 選配：定期不定額的「建議金額」（待你決定要不要做）

手動的定期不定額，你目前是自己決定每次買多少。系統可以在待確認畫面顯示一個「建議金額」，規則由你在範本上設定，例如：以「你的平均成本」或「近 N 日均價」為基準，現價低於基準 5% 時加碼 NT$1,000、高於基準 5% 時減碼 NT$1,000。這只是參考，你隨時可以改成自己要的金額。

#### 元大規則的來源（截至查證時）

- 台股定期定額：每筆手續費均一價 1 元、資金於扣款日前一營業日 16:00 前備妥、設定日遇假日順延到下一個交易日、餘額不足當次不執行也不補扣。
- 複委託定期定額：由元大依指定日期統一交易、成交價為整體成交均價、碎股至小數點後第 5 位、成交回報以平台／簡訊／語音通知。
- 手續費為官網活動價，活動期間至 2026/12/31，之後可能調整。

## 8. 用舊規格情境驗證

已用五支小型模擬程式驗證，共 101 項檢查全部通過。

**`verify_model.py`（20 項）**：把舊 PROJECT.md 的常見記帳情境用新模型各記一遍，檢查餘額與淨值。涵蓋一般收支、轉帳（淨值不變）、換匯、買台股、複委託跨幣別買股、股息、信用卡刷卡與還款、代付與朋友還款、Line Pay 點數加信用卡拆帳、退款、餘額調整、貸款本息還款（只有利息減少淨值）、BTC 小數累加不失真。

**`verify_holdings.py`（25 項）**：驗證持倉、成本與損益。涵蓋台股買入含手續費與部分賣出、複委託兩次買入與部分賣出（美元成本與台幣成本同時追蹤）、股價損益加匯兌損益恆等於台幣總損益、美股股息預扣稅、拆股與併股總成本不變、定期定額碎股 4 位小數累加不失真、隱含匯率輸入檢查。預期數字都是先用手算好再與程式比對。

**`verify_settlement.py`（20 項）**：驗證交割日推算與待交割款。涵蓋台股一般日 T+2、春節封關（2/11 成交 → 2/13，而不是 2/24）、複委託買 T+1／賣 T+2、美國休市日順延、單一日曆與雙日曆會得到不同結果；以及成交日到交割日之間銀行餘額不變、股票已入帳、待交割款正確、淨值在成交日與交割日前後連續（買入與賣出各一組），並對照「不計待交割款會多算 135,192」。程式內的休市日是測試用假設日曆，用來驗證邏輯，不代表真實的休市安排。

**`verify_recurring.py`（17 項）**：驗證定期定額流程。涵蓋預計扣款日推算（週六順延、春節休市順延、設在「僅辦理交割」日要順延到有交易的日子、每月多個日期、31 號遇小月取月底）、資金備妥提醒日、排程重複執行與漏跑補跑不重複、待確認不影響餘額與持倉、確認後以實際金額入帳（可與預計不同）、略過後不會重新產生、碎股 5 位小數不失真。

**`verify_recurring_modes.py`（19 項）**：驗證兩種執行方式並存。涵蓋交割天數預設值（券商定期定額 0、手動下單取證券帳戶設定 2、範本可覆寫）、手動下單延後到別天買時交割日依實際成交日重算、手動改過的交割日不被覆蓋（不需額外欄位，以比對自動值判斷）、兩種並存時待交割款只來自手動下單那筆、成交到交割之間銀行餘額不變且淨值連續、略過與去重。

五支程式保留在專案裡，之後改成 JavaScript 版時可以當測試基準。

## 9. 不在 v1 範圍、以及尚待確認

- **預算功能**：舊規格沒有，v1 不做，但資料庫不會擋住之後加。
- **成本計算法**：預設平均成本（與舊版一致）；先進先出（FIFO）不含。
- **交割規則會變動、也因券商而異**：預設的交割天數與日曆是依券商公開資訊整理（台股 T+2；複委託買 T+1、賣 T+2、台灣與美國皆營業才算），你的券商若不同，請在證券帳戶設定調整。
- **臨時休市**：颱風、地震等臨時休市無法預先得知，需要你手動補「休市日」並修正交割日。
- **元大定期定額扣款時點**：已由你確認為扣款當天；元大公開文件沒有明文寫出，此項依你的實際經驗定案。
- **定期不定額的建議金額**：選配功能，待你決定要不要做，見 7.5。
- **複委託定期定額庫存的賣出限制**：元大作業手冊載明每日一盤、以當天定期定額賣出的加權平均價成交，整股要轉入一般庫存需 2 至 3 個營業日才能盤中交易。v1 不特別處理，賣出時照一般賣出記錄成交結果即可。
- **證交所資料是否能由排程自動匯入**：證交所提供公開的開休市資料，格式已確認；但能否從 Apps Script 穩定抓取，要到實作時才能驗證。失敗時改為手動貼上或匯入，不影響其他功能。
- **用美元帳戶買美股**：台幣成本用買入當日匯率估算並標示「估算」；你目前是用台幣買，不受影響。
- **v1 不含的股票情境**：融資融券、當沖、期貨選擇權、合併換股與下市。除權息（現金股利、配股）與拆併股都已支援。
- **券商費率**：費率與折扣由你在「證券帳戶設定」填寫，新增交易時只做「建議值」，以你輸入的對帳單金額為準。
- **多使用者／分享**：不含。
- **API 格式**：需要對照個人工作台 Apps Script 的請求／回應格式，讓兩個系統風格一致。（目前只看過工作台的 Sheet 結構，還沒看過它的程式碼。）
- **新網站的 repo**：需要決定放在哪個 GitHub repo、叫什麼名稱。
- **初始分類與選項的種子資料**：下一步會依舊規格的分類範例整理一份給你確認。

## 附錄：實作時的調整（第 1 批）

以下是寫程式時與上面草案不同或補充之處，以程式與此附錄為準：

- **價格表新增「上次有效價」欄**，並容許「現價」欄出現公式錯誤（#N/A 不算壞資料，也不會讓整張表被略過）。
- **證券帳戶設定的欄位拆得更細**：手續費幣別、定期定額固定手續費、定期定額手續費率、定期定額每筆上限、賣出交割天數、交割日曆各自一欄（見 `core/schema.js`）。
- **資產與負債依「餘額正負」判斷**，不依帳戶類型：餘額為正加入資產，為負加入負債（信用卡多繳算資產、銀行透支算負債）。
- **日期與時間全部以文字儲存**（`yyyy-MM-dd`、`yyyy-MM-dd HH:mm:ss`，固定台灣時間），避免 Sheet 自動把它轉成日期物件或受時區影響；所有文字欄位事先設成純文字格式，備註以 `=`、`+`、`-`、`@` 開頭時前面會補一個空白，防止公式注入。
- **登入機制**：裝置授權碼 + PIN。授權碼與 PIN 的雜湊（加鹽 SHA-256）存在 Apps Script 的指令碼屬性，不放在 Sheet；PIN 連續錯 5 次鎖 15 分鐘；登入後發的 session 是無狀態簽章（HMAC），閒置 60 分鐘失效（可在「設定」表調整），撤銷裝置或「登出所有裝置」後立即失效。
- **寫入保護**：所有寫入都在 LockService 鎖內執行；新增交易帶 requestId 防重複送出；修改／作廢需帶 expectedUpdatedAt，資料已被別台裝置改過會回 CONFLICT；每次寫入都在「異動紀錄」留下一列（含裝置名稱）。
- **第 1 批開放的交易類型**：收入、支出、轉帳、換匯、退款、調整。買入／賣出／股息／股數調整在後續批次啟用，伺服器目前會拒絕。
- **系統分類**：「餘額調整」與「股息」（類型＝系統），不出現在一般記帳的分類選單。
