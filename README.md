# 財務管理系統（網頁版）

個人記帳與資產管理：**GitHub Pages 前端（可安裝成 App）＋ Google 試算表當資料庫 ＋ Apps Script 當 API**。
做法與「個人工作台」相同，只是資料與登入都獨立。

目前是 **第 1 批（v0.1.0）**：資料表建立、登入、基本記帳（收入／支出／轉帳／換匯／退款／餘額調整）、帳戶與分類管理、淨資產、月收支、手機版 App。
投資（台股／複委託）、信用卡與貸款、定期、報表等在後續批次加入，資料表已經預先建好。

- 設計文件：[`spec/db-design.md`](spec/db-design.md)（文末附錄列出實作時的調整）

## 一、第一次設定（約 15 分鐘）

### 1. 建立試算表與後端
1. 到 Google 試算表建立一份**空白**試算表，命名為「財務管理」（不要放進共用雲端硬碟）。
2. 選單 **擴充功能 → Apps Script**。
3. 左側齒輪 **專案設定** → 勾選 **「在編輯器中顯示『appsscript.json』資訊清單檔案」**。
4. 回到編輯器：
   - 開啟 `appsscript.json`，把內容整份換成本專案 `dist/appsscript.json`。
   - 開啟 `Code.gs`，把內容整份換成本專案 `dist/Code.gs`（`dist/Code.gs` 是由 `core/` 與 `server/` 自動合併出來的，**不要手動改它**）。
   - 按 **儲存**。
5. 回到試算表，**重新整理頁面**，上方會多出 **「財務系統」** 選單。

### 2. 第一次設定精靈
選單 **財務系統 → 第一次設定（建議從這裡開始）**：

1. 第一次執行 Google 會要求授權。看到「Google 尚未驗證這個應用程式」是正常的（這是你自己的腳本）：**進階 → 前往（不安全）→ 允許**。
2. 精靈會建立所有資料表、預設分類與匯率，然後請你設定 **PIN**（至少 6 碼）。
3. 再輸入這台裝置的名稱（例如「我的手機」），畫面會顯示一組 **裝置授權碼**（`XXXXX-XXXXX-XXXXX-XXXXX`）。
   **這組授權碼只會顯示這一次**，請存進密碼管理員。
4. 最後精靈會安裝每日排程（早上 7 點更新匯率）。

### 3. 部署成網頁應用程式
Apps Script 右上角 **部署 → 新增部署作業**：

- 類型：**網頁應用程式**
- 執行身分：**我**
- 誰可以存取：**所有人**（沒有授權碼與 PIN 什麼都拿不到，見「安全性」）

按 **部署**，複製 **網頁應用程式網址**（`https://script.google.com/macros/s/…/exec`）。
用瀏覽器開這個網址，看到 `{"ok":true,…}` 就代表後端正常。

### 4. 前端放上 GitHub Pages
1. 開啟 `docs/config.js`，把網址貼進 `apiUrl`（不貼也可以，登入畫面的「連線設定」也能填）。
2. 建立 GitHub 儲存庫（建議名稱 `finance-web`）並推送本資料夾（見下方「推上 GitHub」）。
3. 儲存庫 **Settings → Pages → Build and deployment**：Source 選 *Deploy from a branch*，Branch 選 `main`、資料夾選 **`/docs`**。
4. 等一分鐘，開啟 `https://<你的帳號>.github.io/finance-web/`。

### 5. 登入並安裝到手機
1. 輸入 **裝置授權碼** 與 **PIN** 登入（授權碼之後會記在這台裝置，下次只要輸入 PIN）。
2. 手機 Chrome：**⋮ → 安裝應用程式**（或「加到主畫面」）。
3. 其他裝置（電腦、平板）：回到試算表 **財務系統 → 新增裝置授權碼**，每台裝置一組，遺失時可在 **查看或撤銷裝置** 撤銷。

## 二、日常維護

| 想做的事 | 做法 |
|---|---|
| 更新程式 | 重新執行 `npm run build`，把新的 `dist/Code.gs` 貼進 Apps Script；然後 **部署 → 管理部署作業 → 編輯（鉛筆）→ 版本：新版本 → 部署**（網址不會變）。接著在試算表執行 **財務系統 → 初始化／修復資料表**（會補上新欄位，不會動到你的資料）。前端檔案推上 GitHub 即可，手機開啟時會自動更新。 |
| 忘記 PIN | 試算表 **財務系統 → 設定或變更 PIN**（只有試算表擁有者才能執行）。 |
| 手機遺失 | **財務系統 → 查看或撤銷裝置**；或 **登出所有裝置**（立即讓所有登入失效）。 |
| 檢查資料 | **財務系統 → 檢查目前狀態**；App「設定」頁底部也有資料檢查。 |
| 備份 | 試算表 **檔案 → 版本記錄** 會自動保留；也可以 **檔案 → 建立副本**。 |

> 試算表裡可以直接看、直接手動修正資料（欄位順序可以調整，程式是依表頭文字對應的）。
> 但請不要修改或刪除各分頁第一列的表頭文字。

## 三、安全性說明

- 網頁應用程式網址是公開可連的，**保護來自後端驗證**：每個請求都要有登入取得的 session，登入需要「裝置授權碼」＋「PIN」，兩者都在後端以加鹽 SHA-256 雜湊驗證；PIN 連續錯 5 次鎖定 15 分鐘（次數與分鐘可在試算表「設定」分頁調整）。
- 授權碼與 PIN 的雜湊存在 Apps Script 的**指令碼屬性**（不在試算表、不在程式碼），GitHub 儲存庫裡**沒有任何祕密**。
- Session 有效 60 分鐘、閒置自動延長；App 閒置也會自動鎖定。撤銷裝置或「登出所有裝置」立即生效。
- 前端所有使用者輸入都以純文字顯示（不使用 `innerHTML`），試算表中以 `= + - @` 開頭的備註會被加上空白，避免公式注入。
- 後端只請求三個權限：讀寫這份試算表、建立排程、在試算表顯示選單。

## 四、專案結構

```
core/      純邏輯（金額精度、日期、帳本計算、驗證、報表）— 前後端共用、Node 可直接測試
server/    Apps Script 專用（資料表存取、登入、API、初始化、排程、選單）
dist/      由 core/ + server/ 合併出的 Code.gs 與 appsscript.json（貼進 Apps Script 用）
docs/      GitHub Pages 前端（原生 ES Modules，無需建置）；docs/js/core/ 由 build 自動複製
tools/     build-gas.js、build-web.js、dev-server.js（本機試玩）、make-icons.js
tests/     單元／整合／瀏覽器端到端測試
spec/      設計文件
```

## 五、開發

需要 Node 20 以上。

```bash
npm test        # 建置 + 執行全部測試（用真正打包後的 Code.gs 搭配記憶體版 Google 服務）
npm run dev -- --demo   # 本機試玩：http://127.0.0.1:8787 （--demo 會放範例資料；資料只在記憶體，關掉就消失；終端機會印出試玩用的授權碼與 PIN）
```

瀏覽器端到端測試需要 Playwright，未安裝時會自動略過：`npm i -D playwright && npx playwright install chromium`。

## 六、推上 GitHub

```bash
git init -b main
git add .
git commit -m "財務管理系統 第 1 批"
git remote add origin https://github.com/<你的帳號>/finance-web.git
git push -u origin main
```

> GitHub Pages 免費方案需要公開儲存庫。儲存庫內沒有祕密（見安全性說明），但如果你把 `docs/config.js` 填了後端網址，就等於公開了網址；沒有授權碼與 PIN 仍然無法讀寫，你也可以改成不填、在登入畫面手動輸入。
